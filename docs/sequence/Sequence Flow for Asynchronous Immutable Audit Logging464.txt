# 1 Overview

## 1.1 Diagram Id

SEQ-CF-003

## 1.2 Name

Asynchronous Immutable Audit Logging

## 1.3 Description

When a security-sensitive event occurs, the backend service sends a structured audit event to an SQS queue. This decouples the audit process from the user request. A dedicated Lambda function then processes the event and writes it to an immutable storage location (e.g., S3 with Object Lock), ensuring a tamper-proof audit trail.

## 1.4 Type

🔹 ComplianceFlow

## 1.5 Purpose

To maintain a tamper-proof audit trail for accountability, security investigations, and compliance, fulfilling the requirements of US-111 and REQ-MON-001.

## 1.6 Complexity

High

## 1.7 Priority

🚨 Critical

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-BE-HOST
- Amazon SQS
- AWS Lambda
- Amazon S3 / CloudWatch Logs

## 1.10 Key Interactions

- A user logs in, triggering an action in the MOD-USERS service.
- The service constructs a structured JSON payload for the `USER_LOGIN_SUCCESS` audit event.
- The service sends this event as a message to a dedicated SQS 'audit-events' queue.
- The primary user request completes and returns a response immediately.
- An AWS Lambda function consumes the message from the SQS queue.
- The Lambda validates the event schema and writes the event to an S3 bucket with Object Lock enabled.
- If writing fails, the message is sent to a Dead-Letter Queue (DLQ) for investigation.

## 1.11 Triggers

- A security-sensitive event occurs: User Login Success/Failure, Subscription Change, Account Deletion Request, Data Export Request.

## 1.12 Outcomes

- A secure, immutable record of the security-sensitive event is created.
- The audit trail is logically and physically separate from application logs.
- The performance of the user-facing request is not impacted.

## 1.13 Business Rules

- Audit logs must be retained for a minimum of 1 year (BR-AUD-002).
- The audit trail storage must be configured to be immutable (WORM - Write Once, Read Many).
- Failures in the audit pipeline must not cause the primary user action to fail.

## 1.14 Error Scenarios

- The message fails to be published to SQS.
- The Lambda processor fails, and the message is moved to the DLQ.

## 1.15 Integration Points

- Amazon SQS
- AWS Lambda
- Amazon S3 (with Object Lock)

# 2.0 Details

## 2.1 Diagram Id

SEQ-CF-003

## 2.2 Name

Implementation: Asynchronous Immutable Audit Logging for Security-Sensitive Events

## 2.3 Description

Provides a detailed technical specification for an asynchronous, decoupled audit logging system. A backend service publishes security-sensitive events to an AWS SQS queue, ensuring the primary user request is not blocked. A dedicated AWS Lambda function consumes these events, validates their schema, and persists them to an immutable AWS S3 bucket configured with Object Lock. This design guarantees a tamper-proof audit trail for compliance (US-111, REQ-MON-001) without impacting application performance or reliability.
