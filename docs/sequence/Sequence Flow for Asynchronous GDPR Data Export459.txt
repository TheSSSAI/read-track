# 1 Overview

## 1.1 Diagram Id

SEQ-CF-002

## 1.2 Name

Asynchronous GDPR Data Export

## 1.3 Description

A user requests an export of their data. The backend queues an asynchronous job that generates a JSON file, stores it securely in a private S3 bucket, generates a pre-signed, time-limited download URL, and emails the link to the user via Amazon SES.

## 1.4 Type

🔹 ComplianceFlow

## 1.5 Purpose

To fulfill the user's 'Right to Data Portability' under GDPR and CCPA, as specified in REQ-USR-001.

## 1.6 Complexity

High

## 1.7 Priority

🚨 Critical

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-FE-MOBILE
- REPO-BE-HOST
- Amazon SQS
- Amazon S3
- Amazon SES

## 1.10 Key Interactions

- User taps 'Export My Data'.
- Backend creates a data export job record and publishes a message to an SQS queue.
- A backend worker (e.g., Lambda/Hangfire) consumes the message.
- The worker fetches all user data (library, sessions) and formats it into a JSON file.
- The file is uploaded to a secure, private S3 bucket.
- The worker generates a pre-signed S3 URL valid for 24 hours.
- The worker uses Amazon SES to email the download link to the user.
- A separate cleanup process deletes the file from S3 after its expiration.

## 1.11 Triggers

- User initiates a data export request.

## 1.12 Outcomes

- The user receives an email with a secure link to download their personal data in JSON format.

## 1.13 Business Rules

- The download link must expire after 24 hours.
- The exported file must be permanently deleted from storage after 24 hours.
- The process must be asynchronous to avoid timing out the user's request.

## 1.14 Error Scenarios

- The background job fails during data aggregation.
- The email fails to send.
- The S3 upload fails.

## 1.15 Integration Points

- Amazon SQS
- Amazon S3
- Amazon SES

# 2.0 Details

## 2.1 Diagram Id

SEQ-CF-002

## 2.2 Name

Implementation of Asynchronous GDPR Data Export Flow

## 2.3 Description

Provides a detailed technical specification for the asynchronous process of exporting user data in compliance with GDPR 'Right to Data Portability' (REQ-USR-001). The sequence is initiated by a user request, which triggers a decoupled background job via Amazon SQS. A Hangfire worker processes the job, generates a JSON file, uploads it to a secure S3 bucket, generates a time-limited pre-signed URL, and emails the link to the user via Amazon SES. The entire process is audited for compliance.
