# 1 Overview

## 1.1 Diagram Id

SEQ-OP-002

## 1.2 Name

System Performance Monitoring and Alerting

## 1.3 Description

The production system's performance is continuously monitored. When a key metric, such as P95 API latency, breaches a predefined threshold for a sustained period, an automated alert is triggered, notifying the on-call engineer.

## 1.4 Type

🔹 OperationalFlow

## 1.5 Purpose

To proactively detect and respond to system performance degradation, ensuring compliance with NFRs like REQ-PER-001.

## 1.6 Complexity

Medium

## 1.7 Priority

🚨 Critical

## 1.8 Frequency

Continuous

## 1.9 Participants

- REPO-BE-HOST
- AWS CloudWatch
- Amazon SNS

## 1.10 Key Interactions

- The backend API is serving production traffic.
- Each request's latency is captured as a metric in AWS CloudWatch.
- A database query slows down, causing the P95 latency for the /api/v1/dashboard endpoint to exceed 200ms.
- A CloudWatch Alarm, configured to monitor this metric, enters the 'ALARM' state after the threshold is breached for 5 consecutive minutes.
- The alarm triggers an action to publish a message to an Amazon SNS topic.
- The SNS topic sends notifications to subscribed endpoints (e.g., PagerDuty, Slack, email).
- The on-call engineer is alerted and begins investigating the issue using dashboards and logs.

## 1.11 Triggers

- A key performance indicator (KPI) breaches its defined threshold.

## 1.12 Outcomes

- The operations team is promptly notified of a performance issue.
- Mean Time To Detection (MTTD) for production issues is minimized.

## 1.13 Business Rules

- Alerts must be configured for critical NFRs, including latency and error rates.
- Alert thresholds must be tuned to avoid excessive noise (alert fatigue).

## 1.14 Error Scenarios

- A misconfigured alarm fails to trigger during an incident.
- A flapping alarm generates excessive notifications.

## 1.15 Integration Points

- AWS CloudWatch Alarms
- Amazon SNS

# 2.0 Details

## 2.1 Diagram Id

SEQ-OP-002-IMPL

## 2.2 Name

Implementation of Automated Performance Degradation Alerting

## 2.3 Description

Technical sequence for monitoring backend API performance. The ASP.NET Core host, instrumented with OpenTelemetry, exports request latency metrics to AWS CloudWatch. A pre-configured CloudWatch Alarm, defined via AWS CDK, monitors the P95 latency of critical endpoints against a 200ms SLO. Upon a sustained breach, the alarm triggers an Amazon SNS topic, which fans out notifications to on-call systems like PagerDuty, ensuring rapid incident response.
