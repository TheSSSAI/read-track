# 1 Overview

## 1.1 Diagram Id

SEQ-DF-002

## 1.2 Name

Background Vector Embedding Generation for RAG

## 1.3 Description

A periodic background job generates vector embeddings from a user's recent reading history, goals, and vocabulary using an OpenAI model (e.g., text-embedding-ada-002). These embeddings are stored in Amazon OpenSearch Serverless to power the k-NN search for the recommendation generation process.

## 1.4 Type

🔹 DataFlow

## 1.5 Purpose

To prepare and maintain the contextual data required for the AI recommendation engine to perform efficient similarity searches, as per REQ-AIS-001.

## 1.6 Complexity

High

## 1.7 Priority

🟡 Medium

## 1.8 Frequency

Daily

## 1.9 Participants

- REPO-BE-HOST
- OpenAI Embedding API
- Amazon OpenSearch Serverless

## 1.10 Key Interactions

- A scheduled job is triggered for a user whose data has recently changed.
- The service fetches the user's reading history, goals, and vocabulary.
- This information is concatenated into text chunks.
- The service calls the OpenAI text-embedding API to get a vector representation for each chunk.
- The service indexes the resulting vector and metadata (UserId, source text) into the UserContextEmbedding index in Amazon OpenSearch.

## 1.11 Triggers

- A user logs a new reading session or updates a goal.
- A scheduled daily or weekly job runs.

## 1.12 Outcomes

- The vector database is populated with up-to-date embeddings representing the user's interests.
- The AI recommendation system can perform relevant context retrieval.

## 1.13 Business Rules

- Embeddings should be regenerated when a user's reading patterns change significantly.
- The process must handle rate limits of the embedding API.

## 1.14 Error Scenarios

- The OpenAI embedding API call fails.
- The write operation to OpenSearch fails.

## 1.15 Integration Points

- OpenAI Embedding API
- Amazon OpenSearch Serverless

# 2.0 Details

## 2.1 Diagram Id

SEQ-DF-002-IMPL

## 2.2 Name

Implementation: Periodic Generation of User Context Vector Embeddings

## 2.3 Description

Technical sequence for a scheduled background job that generates and stores vector embeddings for user-specific context. The job is triggered by a scheduler (Hangfire), fetches relevant user data from the primary PostgreSQL database, transforms it into text, calls the OpenAI Embedding API to generate vectors, and indexes the resulting embeddings into an Amazon OpenSearch Serverless index. The process is designed for resilience, using Polly policies for external API calls, and includes detailed logging and monitoring.
