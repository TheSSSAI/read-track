# 1 Overview

## 1.1 Diagram Id

SEQ-BP-002

## 1.2 Name

Subscription Tier Reversion on Expiration

## 1.3 Description

When a premium subscription ends, the system automatically reverts the account to the 'Free User' tier. This is triggered either by a webhook from the payment provider or a daily scheduled job that finds expired subscriptions. The user retains their data but is subject to free tier limitations.

## 1.4 Type

🔹 BusinessProcess

## 1.5 Purpose

To manage the subscription lifecycle and correctly enforce feature limitations for users who are no longer paying, as per REQ-BUS-001.

## 1.6 Complexity

Medium

## 1.7 Priority

🔴 High

## 1.8 Frequency

Daily

## 1.9 Participants

- REPO-BE-HOST
- Apple App Store / Google Play Store

## 1.10 Key Interactions

- A webhook (e.g., `SUBSCRIPTION_EXPIRED`) is received OR a scheduled daily job runs.
- The MOD-MONETIZATION service identifies a user whose subscription has ended.
- The service publishes a `SubscriptionTerminated` domain event.
- A handler in the MOD-USERS service consumes this event.
- The handler updates the user's role from 'Premium User' to 'Free User' in the database.
- The next time the user's JWT is refreshed, it will contain the new 'free_user' role, and the UI will apply the corresponding limitations.

## 1.11 Triggers

- A scheduled daily job executes.
- A server-to-server webhook for subscription cancellation/expiration is received.

## 1.12 Outcomes

- The user's account is correctly downgraded to the Free tier.
- Free tier limitations are applied on the user's next session.
- No user data (e.g., books over the limit) is deleted.

## 1.13 Business Rules

- Users retain premium access until the end of the current billing period, even if they cancel early.
- Existing data that exceeds free limits is not deleted, but the user is blocked from adding new data until they are within limits.

## 1.14 Error Scenarios

- The scheduled job fails to run.
- An error occurs while updating a user's role, leaving them in an incorrect state.

## 1.15 Integration Points

- Apple App Store / Google Play Billing webhooks (SI-006)

# 2.0 Details

## 2.1 Diagram Id

SEQ-BP-002

## 2.2 Name

Implementation: Subscription Tier Reversion on Expiration

## 2.3 Description

A detailed technical sequence for the automated business process of reverting a user's subscription tier from 'Premium' to 'Free' upon expiration. The process is triggered by one of two mechanisms: a server-to-server webhook from an external payment provider (e.g., Apple/Google) or a daily recurring background job. The Monetization module identifies the terminated subscription and publishes a 'SubscriptionTerminated' domain event via an in-process message bus (MediatR). A handler in the Users module consumes this event to update the user's role in the primary database, ensuring a decoupled and resilient workflow. All tier changes are logged to an immutable audit trail for compliance.

#### 2.6.1.1 Content

Business Rule (REQ-BUS-001): Existing user data that exceeds the new free tier limits (e.g., >20 books) is NOT deleted. Logic in other modules will prevent adding new items until the user is within limits.

#### 2.6.1.2 Position

bottom

#### 2.6.1.3 Participant Id

*Not specified*

#### 2.6.1.4 Sequence Number

### 2.6.2.0 Content

#### 2.6.2.1 Content

Webhook Idempotency: The webhook handler must be idempotent. It should check the current subscription status before processing to safely handle duplicate events from the payment provider.

#### 2.6.2.2 Position

top

#### 2.6.2.3 Participant Id

REPO-BE-HOST

#### 2.6.2.4 Sequence Number

1.1

### 2.6.3.0 Content

#### 2.6.3.1 Content

The user's JWT is not immediately invalidated. The new 'FreeUser' role will be reflected in the JWT payload the next time it is refreshed, applying the UI and API limitations on their next session.
