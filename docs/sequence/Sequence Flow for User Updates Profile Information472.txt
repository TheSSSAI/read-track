# 1 Overview

## 1.1 Diagram Id

SEQ-FF-004

## 1.2 Name

User Updates Profile Information

## 1.3 Description

An authenticated user navigates to their profile settings and updates their display name. The change is validated and persisted by the backend, and the updated information is reflected in the client UI.

## 1.4 Type

🔹 FeatureFlow

## 1.5 Purpose

To allow users to manage and personalize their own profile information as part of basic user management (REQ-USR-001).

## 1.6 Complexity

Low

## 1.7 Priority

🟡 Medium

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-FE-MOBILE
- REPO-BE-HOST

## 1.10 Key Interactions

- User navigates to the 'Account Settings' screen.
- User taps 'Edit' on their profile and enters a new display name.
- User saves the changes.
- The mobile client sends a PUT /api/v1/users/me request with the updated profile data.
- The backend API receives the request and validates the JWT to identify the user.
- The MOD-USERS service performs input validation on the new display name (e.g., length, content).
- The service updates the `displayName` field on the `User` entity in the database.
- The API returns a 200 OK response with the updated user profile.
- The client updates its local state and UI to show the new display name.

## 1.11 Triggers

- User submits the profile edit form.

## 1.12 Outcomes

- The user's profile information is successfully updated in the system.
- The change is immediately visible to the user in the app.

## 1.13 Business Rules

- Users can only update their own profile.
- Input validation rules must be enforced on all user-submitted data.

## 1.14 Error Scenarios

- The new display name fails validation (e.g., it's too long or contains invalid characters).
- A database error occurs while saving the update.
