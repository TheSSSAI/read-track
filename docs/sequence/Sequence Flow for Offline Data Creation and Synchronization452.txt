# 1 Overview

## 1.1 Diagram Id

SEQ-DF-001

## 1.2 Name

Offline Data Creation and Synchronization

## 1.3 Description

When the user is offline, the mobile client persists new data (e.g., reading sessions) to a local Isar database. Upon restoration of network connectivity, a background synchronization service pushes the local changes to the backend and fetches remote updates, using a 'last write wins' strategy for conflict resolution.

## 1.4 Type

🔹 DataFlow

## 1.5 Purpose

To provide core application functionality without a persistent internet connection, enhancing user experience and resilience as per REQ-OFF-001.

## 1.6 Complexity

High

## 1.7 Priority

🔴 High

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-FE-MOBILE
- REPO-BE-HOST

## 1.10 Key Interactions

- Client's connectivity listener detects an offline state.
- User logs a new reading session.
- The repository layer writes the new session data to the local Isar database, marking it as 'unsynced'.
- The connectivity listener later detects an online state.
- A background sync service reads all 'unsynced' records.
- The service sends the queued data to the backend API in batches.
- Upon successful push (2xx response), the client marks the local records as 'synced'.
- The client then fetches any new data from the server that may have been created on another device.

## 1.11 Triggers

- User performs a data-mutating action while offline.
- Network connectivity is restored after being offline.

## 1.12 Outcomes

- User data is eventually consistent between the local device and the server.
- Users can use core features of the app seamlessly offline.

## 1.13 Business Rules

- A 'last write wins' conflict resolution strategy is used, based on a client-side timestamp.
- Features requiring real-time data (e.g., searching new books, AI suggestions) are disabled and their UI reflects this state.

## 1.14 Error Scenarios

- A conflict occurs during synchronization where the server has a newer version.
- The app is terminated before synchronization is complete (sync should resume on next launch).

# 2.0 Details

## 2.1 Diagram Id

SEQ-DF-001

## 2.2 Name

Implementation of Offline-First Data Synchronization

## 2.3 Description

This sequence details the complete data flow for creating data on the mobile client while offline and its subsequent synchronization with the backend server upon network restoration. The process is divided into two main phases: 1) Offline data persistence to the local Isar database, and 2) Asynchronous data push to the backend API via a background service. It implements the Repository pattern to abstract data sources and a 'last write wins' strategy for conflict resolution, ensuring eventual consistency as required by REQ-OFF-001.
