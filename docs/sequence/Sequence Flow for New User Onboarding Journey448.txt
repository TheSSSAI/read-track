# 1 Overview

## 1.1 Diagram Id

SEQ-UJ-001

## 1.2 Name

New User Onboarding Journey

## 1.3 Description

Guides a first-time user through the initial setup process after successful authentication. The flow includes prompting the user to set a primary goal and add their first book, then notifies the backend that onboarding is complete. This sequence is designed to maximize user engagement from the start.

## 1.4 Type

🔹 UserJourney

## 1.5 Purpose

To successfully onboard new users by personalizing their experience and familiarizing them with core application features, as per REQ-ONB-001.

## 1.6 Complexity

Medium

## 1.7 Priority

🚨 Critical

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-FE-MOBILE
- REPO-BE-HOST

## 1.10 Key Interactions

- User completes social sign-in.
- Mobile client displays multi-step onboarding UI.
- User is prompted to set a yearly reading goal.
- User is guided to search for and add a 'Currently Reading' book.
- Client sends onboarding data (e.g., initial goal, book) and a completion flag to the backend.
- The user's `hasCompletedOnboarding` flag is set to true in the database.
- User is navigated to the main dashboard.

## 1.11 Triggers

- A new user logs in for the very first time.

## 1.12 Outcomes

- A user account is created and personalized with an initial goal and book.
- The user understands the basic functionality of the app.
- The user's onboarding status is permanently recorded.

## 1.13 Business Rules

- Onboarding flow is mandatory for all new users upon their first login.
- Users can skip optional steps like setting a goal or adding a book.

## 1.14 Error Scenarios

- Network failure prevents saving the initial goal or book.
- User closes the app mid-onboarding (state should be saved to resume).

# 2.0 Details

## 2.1 Diagram Id

SEQ-UJ-001-IMPL

## 2.2 Name

Implementation: New User Onboarding Journey

## 2.3 Description

Provides a detailed technical specification for the new user onboarding flow as per REQ-ONB-001. This sequence begins after a first-time user's successful authentication, where the client application, driven by a state management component (e.g., Riverpod Provider/BLoC), guides them through a multi-step UI. The flow orchestrates user input for an initial reading goal and book selection, handles state persistence for resilience, and culminates in a single API call to the backend to mark onboarding as complete and persist the initial user data. The backend processes this request transactionally.

## 2.6.0.0.0.0.0 Notes

### 2.6.1.0.0.0.0 Content

#### 2.6.1.1.0.0.0 Content

Client-Side State Persistence: If the user closes the app mid-onboarding, the `OnboardingBloc`'s current state (including step and any entered data) must be persisted to local storage (Isar). On app restart, the initial navigation logic must check for this persisted state and resume the onboarding flow from where the user left off.

### 2.6.2.0.0.0.0 Content

#### 2.6.2.1.0.0.0 Content

Transactional Integrity: The backend operation to create the initial goal, add the book, and update the user's status MUST be atomic. Using a single `DbContext.SaveChangesAsync()` call within the command handler ensures all changes are committed in one transaction or none are.
