# 1 Overview

## 1.1 Diagram Id

SEQ-FF-003

## 1.2 Name

Ad Delivery for Free Users

## 1.3 Description

For users on the 'Free User' tier, the mobile client integrates with the Google AdMob SDK to request and display ads at specific placement points, such as banner ads or interstitial ads, while respecting user consent choices for personalized advertising.

## 1.4 Type

🔹 FeatureFlow

## 1.5 Purpose

To generate revenue from non-paying users as part of the freemium business model, as required by REQ-ADS-001.

## 1.6 Complexity

Medium

## 1.7 Priority

🟡 Medium

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-FE-MOBILE
- Google AdMob SDK

## 1.10 Key Interactions

- User navigates to a screen with an ad placement (e.g., statistics page).
- The client state management confirms the user's tier is 'Free User'.
- An ad component initializes the Google AdMob SDK and requests an ad for a specific ad unit ID.
- The AdMob service returns an ad creative, which is then displayed in the designated view.
- The client also tracks events (e.g., reading session logged) to trigger interstitial ads according to frequency rules (e.g., after every 3rd session).

## 1.11 Triggers

- A 'Free User' views a screen with an ad placement.
- A 'Free User' completes an action that triggers a frequency-capped ad.

## 1.12 Outcomes

- Advertisements are displayed to Free Users.
- Ad impression and click events are tracked by the AdMob SDK.

## 1.13 Business Rules

- Ads must not be displayed to 'Premium User' accounts.
- Ad placement and frequency must be configured to minimize disruption to the core user experience.
- User consent for personalized advertising (e.g., App Tracking Transparency on iOS) must be respected.

## 1.14 Error Scenarios

- The AdMob SDK fails to load an ad (no-fill), and the UI gracefully handles the empty space.
- A client-side bug causes ads to be shown to premium users.

## 1.15 Integration Points

- Google AdMob SDK

#### 2.6.2.1.0 Content
