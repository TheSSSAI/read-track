# 1 Overview

## 1.1 Diagram Id

SEQ-IF-002

## 1.2 Name

Resilient External API Call (Google Books)

## 1.3 Description

The backend service for adding a book calls the Google Books API using an HttpClient wrapped with Polly resilience policies. This automatically handles transient errors through retries with an exponential backoff and jitter strategy.

## 1.4 Type

🔹 IntegrationFlow

## 1.5 Purpose

To ensure that interactions with critical external dependencies are reliable and can withstand transient failures, as per REQ-REL-001.

## 1.6 Complexity

Medium

## 1.7 Priority

🔴 High

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-BE-HOST
- Google Books API

## 1.10 Key Interactions

- A user searches for a book by ISBN.
- The MOD-READING service uses a typed HttpClient to call the Google Books API.
- The Polly Retry Policy intercepts the outgoing request.
- The Google Books API returns a transient error (e.g., 503 Service Unavailable).
- The Polly policy catches the exception, waits for a calculated delay (exponential backoff + jitter), and retries the request.
- On the second attempt, the API responds successfully.
- The service processes the successful response.

## 1.11 Triggers

- Any backend service call to an external API (Google Books, OpenAI, Contentful).

## 1.12 Outcomes

- The API call eventually succeeds despite an initial transient failure.
- The user experience is uninterrupted.

## 1.13 Business Rules

- A limited number of retries (e.g., 3) should be attempted.
- An exponential backoff strategy must be used to avoid overwhelming a recovering service.

## 1.14 Error Scenarios

- The external API continues to fail after all retry attempts are exhausted, which would then trigger a Circuit Breaker.

## 1.15 Integration Points

- Google Books API (SI-005)

# 2.0 Details

## 2.1 Diagram Id

SEQ-IF-002

## 2.2 Name

Implementation of Resilient Google Books API Integration with Polly Retry Policy

## 2.3 Description

This diagram details the technical implementation of a resilient call from the backend service to the external Google Books API. It utilizes an IHttpClientFactory-managed typed HttpClient wrapped with a Polly PolicyWrap containing both a Retry and a Circuit Breaker policy. The sequence demonstrates the retry mechanism handling a transient HTTP 503 error, fulfilling the resilience requirements outlined in REQ-REL-001 and REQ-REL-002.
