# 1 Overview

## 1.1 Diagram Id

SEQ-CF-001

## 1.2 Name

GDPR Compliant Account Deletion

## 1.3 Description

A user initiates the permanent deletion of their account. The backend performs a hard delete of PII from primary data stores via an asynchronous job and triggers a separate process to find and anonymize their identity in retained application logs to comply with privacy regulations.

## 1.4 Type

🔹 ComplianceFlow

## 1.5 Purpose

To fulfill the user's 'Right to Erasure' under GDPR and CCPA, as specified in REQ-USR-001.

## 1.6 Complexity

High

## 1.7 Priority

🚨 Critical

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-FE-MOBILE
- REPO-BE-HOST

## 1.10 Key Interactions

- User confirms 'Delete Account' in the client.
- Client sends a DELETE /api/v1/users/me request.
- The MOD-USERS service receives the request and enqueues an async deletion job.
- The job performs a hard delete of all PII and user-generated content from the primary database.
- The job triggers a separate sub-process to anonymize the user's PII (e.g., user ID, IP address) in application logs.
- An immutable audit log of the account deletion event is created (containing a non-identifiable ID).
- The user's session is invalidated, and they are logged out.

## 1.11 Triggers

- User confirms their request to permanently delete their account.

## 1.12 Outcomes

- All of the user's PII and generated content is permanently removed from the system.
- The user can no longer log in to the application.
- The action is logged for audit purposes.

## 1.13 Business Rules

- The deletion process must be irreversible (hard delete, not soft delete).
- The account deletion event itself must be logged for auditing, but without any PII.

## 1.14 Error Scenarios

- The deletion process fails partway through, leaving orphaned data. Must have retry/recovery logic.
- The log anonymization process fails to find all instances of the user's PII.

# 2.0 Details

## 2.1 Diagram Id

SEQ-CF-001

## 2.2 Name

GDPR Compliant Account Deletion with Asynchronous Processing and Immutable Auditing

## 2.3 Description

Implementation sequence for a user-initiated permanent account deletion. The flow immediately invalidates the user's session and enqueues an asynchronous job to perform a hard delete of PII from the primary database. A subsequent sub-process anonymizes the user's identity in retained application logs. All critical stages are recorded in a separate, immutable audit trail to comply with GDPR's 'Right to Erasure' (REQ-USR-001).
