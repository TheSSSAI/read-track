# 1 Overview

## 1.1 Diagram Id

SEQ-EH-001

## 1.2 Name

External API Failure with Circuit Breaker and Fallback

## 1.3 Description

If the Google Books API is persistently unavailable, the Polly Circuit Breaker policy opens, preventing further calls. The system then executes a defined fallback action, such as allowing the user to enter book details manually, and transitions the circuit to Half-Open after a cooldown to test for recovery.

## 1.4 Type

🔹 ErrorHandling

## 1.5 Purpose

To protect the system from cascading failures and provide a degraded but functional user experience, as specified in REQ-REL-001.

## 1.6 Complexity

Medium

## 1.7 Priority

🔴 High

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-FE-MOBILE
- REPO-BE-HOST
- Google Books API

## 1.10 Key Interactions

- The Google Books API fails requests consistently.
- The Polly Circuit Breaker reaches its failure threshold and opens.
- A new request to search for a book is made.
- The Circuit Breaker immediately throws a `BrokenCircuitException`.
- The application code catches this exception and returns a specific error response to the client indicating manual entry is available.
- The client UI adapts, showing fields for manual Title and Author entry.
- After the break duration, the circuit becomes 'Half-Open', allowing one test request through to check for service recovery.

## 1.11 Triggers

- An external dependency becomes unresponsive for a sustained period.

## 1.12 Outcomes

- The application remains stable and avoids being blocked by a failing service.
- The user is gracefully informed of the issue and provided an alternative workflow.

## 1.13 Business Rules

- Each critical external dependency must have a defined fallback behavior.
- The system must monitor and alert when a circuit breaker opens.

## 1.14 Error Scenarios

*No items available*

## 1.15 Integration Points

- Google Books API (SI-005)

# 2.0 Details

## 2.1 Diagram Id

SEQ-EH-001

## 2.2 Name

External API Failure with Polly Circuit Breaker and Fallback

## 2.3 Description

Demonstrates the system's resilience when a critical external dependency (Google Books API) fails. The sequence shows how repeated failures lead to a Polly Circuit Breaker policy opening. Subsequent requests are immediately rejected, triggering a fallback mechanism that allows the user to perform a degraded but functional action (manual book entry). The diagram also covers the transition to the half-open state for service recovery probing, as required by REQ-REL-001.
