# 1 Overview

## 1.1 Diagram Id

SEQ-AF-002

## 1.2 Name

Secure JWT Refresh with Token Rotation

## 1.3 Description

The mobile client transparently uses a long-lived refresh token to obtain a new short-lived JWT access token when the current one expires. The process uses refresh token rotation, where a new refresh token is issued with every request, invalidating the old one to enhance security.

## 1.4 Type

🔹 AuthenticationFlow

## 1.5 Purpose

To maintain a persistent user session securely while minimizing the exposure of a long-lived access token and preventing token reuse attacks, as per standard security practices mentioned in REQ-USR-001.

## 1.6 Complexity

Medium

## 1.7 Priority

🔴 High

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-FE-MOBILE
- REPO-BE-HOST

## 1.10 Key Interactions

- Client's HTTP interceptor detects a 401 Unauthorized response from an API call.
- Interceptor sends the stored refresh token to a dedicated /token/refresh endpoint.
- Backend validates the refresh token against its database, ensuring it is valid and has not been used before.
- Backend revokes the used refresh token.
- Backend issues a new short-lived access token and a new long-lived refresh token.
- Client securely stores the new tokens.
- The interceptor retries the original API request with the new access token.

## 1.11 Triggers

- An API call is attempted with an expired access token.

## 1.12 Outcomes

- A new, valid access token is issued.
- The user's session is extended without interruption.
- The original failed API request succeeds on retry.

## 1.13 Business Rules

- Refresh tokens must be single-use to enhance security (refresh token rotation).
- If an invalid or already-used refresh token is presented, all of that user's sessions should be invalidated as a security precaution.

## 1.14 Error Scenarios

- Refresh token is expired, stolen, or has been revoked.
- Network error during the token refresh request.
