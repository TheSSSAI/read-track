# 1 Overview

## 1.1 Diagram Id

SEQ-FF-002

## 1.2 Name

Freemium Limit Enforcement Check

## 1.3 Description

Before a 'Free User' performs a limited action (e.g., adding a book), the backend API checks if they have reached their limit. If so, the action is blocked with a specific error code, which the client uses to display an upgrade prompt.

## 1.4 Type

🔹 FeatureFlow

## 1.5 Purpose

To enforce the business rules of the freemium model and create an upsell opportunity, as per REQ-FRE-001.

## 1.6 Complexity

Low

## 1.7 Priority

🔴 High

## 1.8 Frequency

OnDemand

## 1.9 Participants

- REPO-FE-MOBILE
- REPO-BE-HOST

## 1.10 Key Interactions

- A 'Free User' attempts to add their 21st book.
- The client sends a POST /api/v1/library request.
- An authorization policy or service logic inspects the user's 'Free User' role.
- The service queries the database to count the user's current number of library items.
- The service determines the user is at the 20-item limit.
- The service rejects the request with a specific error code (e.g., 402 Payment Required) and a message.
- The client's global error handler intercepts the specific error code and displays a standardized upgrade prompt UI.

## 1.11 Triggers

- A 'Free User' attempts an action that is limited by their subscription tier.

## 1.12 Outcomes

- The action is prevented.
- The integrity of the freemium business model is maintained.
- The user is informed about the limitation and prompted to upgrade.

## 1.13 Business Rules

- Free Users are limited to 20 items.
- Free Users are limited to one active goal.
- Free Users are limited to 5 AI suggestions per month.

## 1.14 Error Scenarios

- The limit check logic contains a bug, incorrectly blocking or allowing an action.

*No items available*
